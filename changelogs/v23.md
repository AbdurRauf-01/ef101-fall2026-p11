# Changelog

Older versions: see the `changelogs/` folder (`v22.md`, `v21.md`, `v20.md`, and `v19.md` and earlier on GitHub).

## v23 (14 Nov 2026)

CPU and CPU family release. The database schema is unchanged. Tests: 313 of 313 pass (312 of 312 when the optional QR-decoder packages are not installed; 303 of 312 without segno).

### Added
- **CPU and CPU family lists on the Add / Edit form.** Both boxes are text boxes with a drop-down list that narrows as you type (about 240 common CPU models and 40 families: Intel Core, Core Ultra, Pentium, Celeron, Xeon, AMD Ryzen, Ryzen AI, Threadripper, EPYC, Athlon and older, Apple M-series, Snapdragon X; desktop and laptop). The lists are suggestions: any other CPU model can still be typed.
- **CPU must match its family.** `backend/cpu_catalog.py` reads the family out of the CPU name with pattern rules (`Intel Core i5-12400` is `Core i5`, `AMD Ryzen 7 5700G` is `Ryzen 7`), so models released later still match. `validate_asset()` rejects a pair that does not match (for example `Intel Core i5-12400` with `Core i3`) and nothing is saved. A CPU the rules do not recognise must use the family `Other`; a recognised CPU cannot use `Other`. A family typed in another case (`core i5`) is saved as listed (`Core i5`).
- `frontend/static/cpu-fields.js`: picking or typing a CPU fills the family and shows a hint when the two do not match. The server checks again on Save, so the script only helps.
- `/api/cpu-family?cpu=...` returns the family of a CPU name (`null` when not recognised).
- 16 new checks in `backend/test_app.py` (catalog is clean, 24 CPU names give the right family, six rejection cases, case handling, Windows-style CPU text, edit, the lookup route, the form lists, every demo asset passes).
- **Launcher menu (all three launchers and `run-tests.*`).** When something is missing the scripts show it with the official links (python.org, pypi.org) and offer four choices: 1 install automatically into `venv/` (default), 2 install system-wide yourself (links and the exact `pip install --user` command are shown, then Y/N: Y checks again and launches, N goes back), 3 continue anyway (may error), 4 exit. If everything is already installed, in `venv/` or system-wide, the app launches straight away and `venv/` is not needed. Python missing gets the same menu from `scripts/bootstrap.sh` / `bootstrap.bat`.
- Risk reduction in the install path: nothing is installed without a choice; no administrator rights are requested by the scripts (Python for the current user only; `--user` for the manual route); packages install with `--only-binary=:all:` so no build scripts run; with no keyboard attached the package menu and the Linux / macOS Python menu install nothing (the Windows Python menu cannot tell, so Enter or no input means choice 1 there). `LAUNCHER_CHOICE=1..4` presets a choice; `--yes` / `--no-install` on the test launcher still work (choice 1 / 3).
- README: the manual steps now cover Windows and macOS separately (Linux has its own section); `git clone` steps start by going to the Downloads folder; the Smart App Control section keeps only the "skip the launchers" route; a note says the project was not tested on macOS (no Mac available, built with AI assistance) and asks for an issue on GitHub if an error occurs.
- README: the first launch may need internet (Flask and segno are downloaded when not already installed); the menu, the optional `venv/` and the risk-reduction steps are described.
- **Reset scripts renamed** from `reset-demo-data.*` to `reset-data.*` (they now do more than reset to demo data).
- **Reset data in the app.** The sidebar's *Reset to demo data* button is replaced by *Reset data*, which opens a dialog with two choices: *Reset to demo data* and *Delete all data* (empty database, six standard places). Confirmed by typing YES, backup saved first (`before-reset-` / `before-delete-`). New route `POST /api/reset-data` (`mode=demo|empty`, `confirm=YES`); the old `/api/reset-demo` address still works (demo data, no question). 4 new checks: the dialog, YES and a valid choice are required, delete leaves 0 assets and the six places and the pages still open, reset to demo restores 40 assets.
- **CPU and CPU family drop-downs look like the other drop-downs.** `frontend/static/combobox.js` draws the filtered list in the app's own style (both themes, keyboard and mouse, matching text in bold, "No match... you can still type your own"); the browser's plain datalist list is only the fallback when JavaScript is off.
- **Reset launcher now has two choices:** 1 reset to the 40 demo assets, 2 delete all data (an empty database with the six standard places). Enter cancels; YES is still asked when there are assets; a backup is always saved first (`before-reset-` or `before-delete-`). New `empty_database()` in `database/db.py`; options `--demo`, `--empty`, `--yes` for scripted use.
- README: every command is now in its own copyable code block (the GitHub copy button), and a new section explains Windows Smart App Control (Mark of the Web, git clone, Unblock on the ZIP, the manual route).

### Fixed
- **Options were not passed on by `scripts/bootstrap.sh` and `bootstrap.bat`**, so `bash scripts/bootstrap.sh test --no-install` (as written in the README) ignored `--no-install`. They are now forwarded to the launcher.
- **Linux two-click launch.** After `chmod +x start.sh`, `scripts/bootstrap.sh` also needed `chmod +x` before a double-click worked: the script reopened itself in a terminal by running `bootstrap.sh` directly. It now runs `bash bootstrap.sh`, so only the file you double-click needs the permission.
- **README test table.** It said the other tests needing nothing but Flask were 282; the segno tests (10) already include the QR decode check, so the figure was 283 in version 22 (303 now).

### Changed
- `APP_VERSION` is `23` (sidebar shows v23). `TEST_TOTAL` in `scripts/launcher.py` is 313.
- `scripts/launcher.py` picks the Python that already has the packages (`venv/` first, then the system Python) instead of always using `venv/`; the old requirements-hash stamp is gone (Flask >= 2.2 and segno >= 1.5 are checked directly). `reset` needs no package (it uses only the standard library).
- `start.*` and `run-tests.*` headers updated.
- README and TEAM_SPLIT updated for version 23. Counts: 313 / 312 / 303 (without segno).

### Notes
- Existing rows are not changed. A row whose CPU and family do not match (for example typed before version 23) is accepted as it is until it is edited; saving an edit then asks for a matching family.
- The family list holds the families that exist today. A family the rules derive but the list does not hold (for example `Apple M7`, if Apple ever makes one) is accepted when typed; it just is not suggested.
