# Changelog

Older versions: see the `changelogs/` folder (`changelogs/v20.md`, `v19.md` and earlier on GitHub).

## v21 (12 Nov 2026)

Backup, printable reports, and reliability release. The database schema is unchanged. Tests: 291 of 291 pass.

### Added
- **Backup data button** in the sidebar footer — saves `backups/inventory.backup-YYYYMMDD-HHMMSS.db` without touching or resetting any data. One click, instant, no confirmation needed.
- **Automatic backup before in-app reset** — `/api/reset-demo` now saves a timestamped backup to `backups/inventory.before-reset-YYYYMMDD-HHMMSS.db` before wiping and reseeding. The success flash message names the backup file.
- **Backups always go to `backups/`** — both in-app reset and script reset (`reset-demo-data.*`) now write backups into a `backups/` subdirectory inside the project folder (created automatically). Previously the script saved the backup in the project root alongside `inventory.db`.
- **Printable asset inventory report** (`/report/assets`, sidebar *Asset Report*, *Print Report* button on the Assets list). A standalone, self-contained HTML page with its own minimal CSS; no sidebar, no nav. Shows all columns (asset ID, manufacturer, model, CPU, CPU family, RAM, storage, GPU, OS, location, IP, status, warranty, purchase date, warranty expiry, fault count), active-filter summary, summary stats (total / operational / faulty / under repair), and a totals row. `@media print` hides the controls and sets print-safe colours; rows do not split across pages.
- **Printable maintenance/fault history report** (`/report/maintenance`, sidebar *Maintenance Report*, *Print Report* button on the Fault History page). Same standalone approach. Shows all maintenance columns (date, asset ID, model, location, status, category, fault description, action taken, technician, cost), summary stats (total events, total cost, assets affected), and a totals row.
- **Print Report buttons** on the Assets list (top-right, next to Export CSV and QR labels) and on the Fault History page (next to Export CSV). Both link to their respective report routes, carrying the same active filters and sort state.
- **Sidebar links** for Asset Report and Maintenance Report under the Maintenance group.

### Fixed
- **In-app reset did not save a backup** — fixed. Before this version, clicking *Reset to demo data* in the sidebar wiped the database with no backup; the script reset did save one. Both now save to `backups/`.
- **Script reset backup location** — `scripts/launcher.py` now puts the backup in `backups/` (created if needed) instead of next to `inventory.db` in the project root.
- **Reset confirm dialog updated** — the sidebar confirm message now mentions that a backup is saved to `backups/` before wiping.

### Changed
- `app.py` gains `import shutil` (used by the backup routes); `APP_VERSION` updated to `21`; `BACKUPS_DIR` constant added (`BASE / "backups"`).
- `scripts/launcher.py`: `reset()` now creates and uses a `backups/` subdirectory; messages updated.
- `templates/base.html`: *Backup data* button added above the existing *Reset to demo data* button; *Asset Report* and *Maintenance Report* links added to the sidebar under Maintenance; breadcrumbs added for the two new report routes; reset confirm dialog updated.
- `templates/assets.html`: *Print Report* button added to the top-right button group.
- `templates/maintenance.html`: *Print Report* button added next to the Export CSV button.
- Two new templates: `templates/report_assets.html`, `templates/report_maintenance.html`.
- README, TEAM_SPLIT, and the report updated for version 21.

### Notes
- Backups are plain SQLite files. Any existing backup in the project root (from the v20 script reset) stays there; new ones go into `backups/`.
- The printable report pages are intentionally standalone (no `base.html` extension): they open in a new context and need no sidebar or nav for printing. The *Print / Save PDF* button calls `window.print()`; in Chrome/Edge, choose *Save as PDF* from the destination drop-down.
- Carried over from v20: a suggested IP can repeat one already used in the same place.
