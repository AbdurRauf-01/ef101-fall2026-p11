# Changelog

Older versions: see the `changelogs/` folder (`changelogs/v19.md` and earlier on GitHub).

## v20 (12 Nov 2026)

Bonus-feature release: QR asset labels and a scanner. The database is unchanged: the same data and the same `schema.sql`. Tests: 285 of 285 pass.

### Added
- **QR codes for every asset, holding the specs as plain text** (asset ID, model, CPU, RAM, storage, GPU, OS, IP, location, warranty expiry, and `Status: ... (as of <date>)`), so a phone can read them with no network although the app is local. The text is a snapshot, so the label must be printed again after a change; the Scan page and asset page are always live. Fault details and costs are not on the label. New module `qr_labels.py` (builds the text, draws the code as SVG with the `segno` package at error-correction level Q with a 4-module border, each field cut to 60 characters, and holds the rule that turns scanned text into an asset ID).
- **QR label card on the asset page** with *Print label* and *Download SVG* (`/assets/<id>/label`, `/qr/<id>.svg`).
- **Printable label sheet** (`/labels`, sidebar *QR Labels*, and a *QR labels* button on the Assets list). It follows the list's search and filters (retired assets only with `show=all`) and prints cleanly: the page chrome is hidden and labels do not split across pages.
- **Scan page** (`/scan`, sidebar *Scan QR*): reads a label with the camera, from an uploaded photo, or from a text box (USB barcode scanners type into it). Reading happens in the browser, with the built-in `BarcodeDetector` when the browser has it and the bundled `jsQR` otherwise. Nothing leaves the computer.
- **Lookup routes**: `/a/<id>` (short address of an asset, kept for older labels and typing; case ignored), `/api/scan-lookup` (what a scanned text means; understands the spec block, a link, `EF101-ASSET:<ID>` and a bare ID).
- Version number (`APP_VERSION`) shown in the sidebar header.
- 56 new checks (285 in total): label text format and limits, scan-text rules (spec block, one-line paste, older formats), lookup and redirects, escaping of odd input, the Host rule on the new routes, label sheet and filters, QR image and download, decoding every generated code back to its text (when `zxing-cpp` or OpenCV is installed), and the app still working when `segno` is missing.

### Changed
- GitHub repository is now `https://github.com/AbdurRauf-01/ef101-fall2026-p11` (app links, About pages, README, TEAM_SPLIT and report). Clone and download-ZIP folder names in the README changed to `ef101-fall2026-p11` and `ef101-fall2026-p11-main`.
- `requirements.txt` gains `segno` (pure Python, no further packages). The launchers install it automatically because the file changed.
- README, TEAM_SPLIT and the report updated for version 20 (`docs/Project-Report-v20.docx` replaces the v19 report); report gains a QR section, routes and a test-table row.
- No-JavaScript-library statement replaced: one file, `static/vendor/jsQR.js` (Apache-2.0, licence in `static/vendor/jsQR.LICENSE.txt`), is bundled; nothing is loaded from the Internet at run time.

### Notes
- The camera works only at `http://127.0.0.1` or `localhost` (a browser rule). The app still answers only to 127.0.0.1 and localhost unless `INVENTORY_ALLOWED_HOSTS` is set, so a phone cannot open the app; it reads the specs from the code.
- The label text is a snapshot made on the day it is printed. The longest label seen (all 40 demo assets, 246 to 270 characters) is a version 14 or 15 code (about 75 modules), printed 34 mm wide on the label sheet.
- Carried over from v19 (not changed in this release): a suggested IP can repeat one already used in the same place, and `/api/reset-demo` does not ask for YES.
